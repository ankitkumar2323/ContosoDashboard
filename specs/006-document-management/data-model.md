# Data Model: Document Upload and Management

## Document

Represents a stored file and its searchable metadata.

| Field | Type | Rules |
|---|---|---|
| DocumentId | int | Primary key; generated by database |
| Title | string | Required; bounded length |
| Description | string? | Optional; bounded length |
| Category | string | Required text value from approved category list |
| Tags | string? | Optional normalized tag representation |
| FileName | string | Original display name only; never used as storage path |
| FilePath | string | Required relative generated path; outside `wwwroot` |
| FileType | string | Required MIME type; max 255 characters |
| FileSize | long | Required; maximum 25 MB |
| Status | string | Quarantined, PendingScan, Available, Rejected, Deleted |
| UploaderId | int | Required foreign key to User |
| ProjectId | int? | Optional foreign key to Project |
| UploadedDate | DateTime | Required UTC timestamp |
| ScannedDate | DateTime? | Set only after scan attempt |

Indexes: `(UploaderId, UploadedDate)`, `(ProjectId, UploadedDate)`, `Category`, `Status`, and metadata fields used by search. Queries must filter authorization before returning results.

## DocumentShare

Represents a sharing relationship within existing authorization boundaries.

| Field | Type | Rules |
|---|---|---|
| DocumentShareId | int | Primary key |
| DocumentId | int | Required foreign key |
| SharedWithUserId | int? | Recipient user when sharing to an individual |
| SharedWithTeam | string? | Recipient team identifier when sharing to a team |
| SharedByUserId | int | Required actor foreign key |
| SharedDate | DateTime | Required UTC timestamp |

At least one recipient field is required. A share cannot expand access beyond the recipient's project membership or role authorization.

## TaskDocument

Joins documents to tasks and preserves project context.

| Field | Type | Rules |
|---|---|---|
| TaskDocumentId | int | Primary key |
| TaskId | int | Required foreign key to TaskItem |
| DocumentId | int | Required foreign key to Document |
| AttachedByUserId | int | Required actor foreign key |
| AttachedDate | DateTime | Required UTC timestamp |

The service must verify that the document and task belong to an accessible project before creating this relationship.

## DocumentAuditEvent

Records upload, scan, preview, download, metadata update, replacement, deletion, and sharing events.

| Field | Type | Rules |
|---|---|---|
| DocumentAuditEventId | int | Primary key |
| DocumentId | int? | Optional for rejected uploads with no document record |
| ActorUserId | int | Required actor |
| Action | string | Required controlled action value |
| Outcome | string | Required success/failure/pending value |
| OccurredDate | DateTime | Required UTC timestamp |
| Details | string? | Optional non-secret diagnostic context |

Audit events are append-only from the application workflow and visible in reports only to administrators.

## Relationships and State Transitions

- User 1-to-many Document as uploader.
- Project 1-to-many Document when a project is selected.
- Document 1-to-many DocumentShare.
- TaskItem many-to-many Document through TaskDocument.
- Document 1-to-many DocumentAuditEvent.
- Upload state: `Quarantined` -> `PendingScan` -> `Available` on clean result; `PendingScan` -> `Rejected` on malware result or failed validation; scanner outage leaves the file `PendingScan` and inaccessible.
- Delete state: authorized permanent deletion removes the file through storage service and then removes or marks the metadata according to the implementation transaction policy; no recovery/trash state is in scope.
